## Рабочий сценарий
Другой разработчик получает чистую копию и должен проверить сборку без ручных настроек IDE. Этот репозиторий станет основой для проектов магазина.

## Что передать коллеге

- `pom.xml` с Java release 21, код точки входа и Maven Wrapper для обеих оболочек. Wrapper скачивает согласованную версию Maven при первом запуске, если её ещё нет в кэше.
- README с выводом `java -version`, командами сборки и точной командой запуска примера из этого задания.
- Отдельный коммит или ветку с демонстрацией исправления. В чистой копии вызов `app.Main check` возвращает `READY` и код 0, вызов `app.Main invalid` пишет подсказку в stderr и возвращает ненулевой код. Папка результатов сборки отсутствует в отслеживаемых файлах.

## Функциональные требования

- [ ] Создать Maven-проект с Java 21 и Maven Wrapper. Добавить точку входа `app.Main`, которая принимает `check` и печатает `READY`. Неизвестный аргумент даёт подсказку и ненулевой код выхода.
- [ ] Добавить `.gitignore`, отдельными коммитами сохранить настройки и реализацию. Сделать небольшое изменение через ветку.
- [ ] Записать в README команды для Windows и Unix. Когда дойдёшь до [тестирования](https://github.com/1ommyFi7in/java-backend-roadmap/blob/main/%D0%A2%D0%B5%D0%BE%D1%80%D0%B8%D1%8F/Unit%20%D0%B8%20integration%20tests.md), подключи JUnit.

## Пример ввода и вывода

```powershell
.\mvnw.cmd verify
java -cp target/classes app.Main check
```

Сборка завершается строкой `BUILD SUCCESS`, программа выводит `READY`. В Unix используется `./mvnw verify`.

## Нефункциональные требования и приёмка

- [ ] Сборка и запуск воспроизводятся из новой рабочей копии с JDK 21. Команды выполняются в терминале, `target/` отсутствует в Git.
